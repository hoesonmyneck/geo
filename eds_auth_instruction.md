# Вход по ЭЦП (NCALayer) — инструкция для нового сайта

Задача: добавить на сайт авторизацию с ЭЦП РК через NCALayer — вторым фактором
после логина и пароля. Сайт живёт на том же сервере, что и проект geo, где
такая схема уже работает. Реализацию нужно повторить один в один, с одним
отличием — свои имена cookies и свой секрет JWT (раздел 2).

Заодно — анимация прорисовки логотипа на странице входа, тоже как в geo
(раздел 7).

---

## 1. Как работает вход

```
1. Пользователь вводит логин и пароль  →  POST /api/auth/login
2. Сервер проверяет пароль.
   ─ у пользователя НЕТ ИИН  →  сразу выдаёт cookies, вход выполнен
   ─ у пользователя ЕСТЬ ИИН →  cookies НЕ выдаёт, возвращает
                                {requires_2fa: true, challenge: "<JWT>"}
3. Браузер открывает WebSocket к NCALayer на компьютере пользователя
   и просит подписать challenge. Пользователь выбирает ключ и вводит пароль
   от него в окне NCALayer.
4. Браузер отправляет {challenge, signature}  →  POST /api/auth/login-2fa
5. Сервер разбирает подпись, проверяет, что подписан именно выданный
   challenge, достаёт из сертификата ИИН и сравнивает с ИИН аккаунта.
   Совпало — выдаёт cookies.
```

ЭЦП включается для конкретного пользователя тем, что администратор вписывает
ему ИИН. Пустой ИИН — вход только по паролю (удобно для служебного admin).

---

## 2. Особенности сервера, которые надо учесть

- **Два сайта на одном хосте делят cookies.** Браузер не разделяет cookies по
  портам: сайт на `:4443` и сайт на другом порту того же адреса видят cookies
  друг друга. В geo токены лежат в cookies `access_token` и `refresh_token`.
  Если новый сайт назовёт их так же, вход в один будет выкидывать из другого.
  **Это единственное отличие от geo:**
  - свои имена cookies, например `site2_access` и `site2_refresh`
    (у refresh-cookie в geo `path="/api/auth"` — оставьте так же);
  - свой `JWT_SECRET`, не общий с geo, — им подписываются и токены сессии,
    и challenge.
- **Сайт отдаётся по HTTPS** (Caddy, сертификаты лежат в `./certs`). Со страницы
  по HTTPS к NCALayer подключаются через `wss://127.0.0.1:13579/`. Оставьте
  запасной `ws://127.0.0.1:14579/` — на части машин защищённый порт не
  поднимается.
- **Корпоративная сеть перехватывает TLS** своим корневым сертификатом.
  `pip install` внутри Docker-сборки падает с `CERTIFICATE_VERIFY_FAILED`.
  В Dockerfile нужно:
  ```dockerfile
  RUN pip install --no-cache-dir \
      --trusted-host pypi.org \
      --trusted-host pypi.python.org \
      --trusted-host files.pythonhosted.org \
      -r requirements.txt
  ```
- Если `docker-compose.yml` на проде отличается от локального (порты и т.п.),
  не коммитьте его, а правьте на сервере руками.

## 3. База данных

У пользователя добавляется поле ИИН:

```python
iin: Mapped[str | None] = mapped_column(String(32), unique=True, nullable=True, index=True)
```

Плюс миграция (в geo это `migrations/versions/0009_user_iin.py`). В админке, в
форме создания и редактирования пользователя, — поле «ИИН» с проверкой ровно
12 цифр; пустое значение сохраняется как `NULL`.

## 4. Бэкенд

Зависимости: `asn1crypto` (разбор CMS), `python-jose` (JWT).

### 4.1. Challenge

JWT, подписанный секретом сайта, живёт 5 минут:

```python
payload = {
    "sub": "eds_challenge",
    "nonce": secrets.token_urlsafe(32),
    "uid": user.id,                        # привязка к пользователю
    "exp": now + timedelta(minutes=5),
}
challenge = jwt.encode(payload, settings.JWT_SECRET, algorithm=settings.JWT_ALGORITHM)
```

При проверке — `jwt.decode(...)` тем же секретом и алгоритмом, плюс проверка
`payload["sub"] == "eds_challenge"`. Истёк или не сошлась подпись — ошибка.

### 4.2. Эндпоинты

**`POST /api/auth/login`** `{login, password}`
- неверный пароль → 401 `Invalid credentials`; заблокирован → 403;
- есть `iin` → `{requires_2fa: true, challenge}`, **cookies не выдавать**;
- нет `iin` → обновить `last_login_at`, выдать cookies, вернуть
  `{requires_2fa: false, user}`.

**`POST /api/auth/login-2fa`** `{challenge, signature}`
1. Декодировать challenge, достать `uid`. Невалиден, истёк или нет `uid` → 401.
2. Загрузить пользователя; нет, неактивен или без ИИН → 401.
3. Разобрать подпись (раздел 4.3) и получить ИИН и ФИО из сертификата.
4. ИИН не совпал с аккаунтом → 401 «ИИН в ЭЦП (…) не совпадает с аккаунтом».
5. Записать ФИО из сертификата в пользователя, обновить `last_login_at`,
   выдать cookies, вернуть пользователя.

Cookies — как в geo: `httponly=True`, `samesite="lax"`, `secure=False`;
refresh-cookie с `path="/api/auth"`. Имена — свои (раздел 2).

### 4.3. Разбор подписи

Как в geo (`backend/app/core/eds.py`, функция `verify_eds_signature`):

1. Проверить challenge (раздел 4.1).
2. `content_info = asn1crypto.cms.ContentInfo.load(base64.b64decode(signature))`;
   `content_info["content_type"].native` должен быть `"signed_data"`.
3. Сертификат подписавшего: `signed_data["certificates"][0].chosen`.
   Сертификатов нет → ошибка.
4. Подписанные данные: `signed_data["encap_content_info"]["content"].native`.
   Пусто → ошибка «подпишите с attached=true». Байты декодировать как UTF-8 и
   сравнить (после `strip()`) с выданным challenge. Не совпало → ошибка.
5. **ИИН**: поле `serialNumber` (OID `2.5.4.5`) в Subject сертификата, формат
   `IIN123456789012`; выделять 12 цифр регуляркой `(\d{12})`. Не нашлось →
   ошибка.
6. **ФИО**: брать `commonName` (OID `2.5.4.3`) — там полное «ФАМИЛИЯ ИМЯ
   ОТЧЕСТВО». Запасной вариант — `surname` (OID `2.5.4.4`) + `givenName`
   (OID `2.5.4.42`). Не делайте склейку основным способом: в сертификатах
   НУЦ РК `givenName` часто содержит только отчество.

Все ошибки разбора — одним типом исключения, эндпоинт превращает его в 401 с
текстом ошибки.

## 5. Фронтенд

### 5.1. Подключение к NCALayer

WebSocket с запасным адресом и таймаутом 3 секунды на каждый:

```js
const NCALAYER_URLS = ['wss://127.0.0.1:13579/', 'ws://127.0.0.1:14579/'];
```

Пробовать по очереди. Ни один не открылся — сообщение «NCALayer не запущен
или недоступен. Запустите NCALayer (pki.gov.kz) и попробуйте снова».

### 5.2. Протокол

1. После открытия соединения **дождаться handshake** от NCALayer вида
   `{"result":{"version":"1.4"}}` и только потом отправлять запрос. Запрос,
   отправленный до handshake, NCALayer может проигнорировать.
2. Запрос на подпись:
   ```js
   const base64Data = btoa(unescape(encodeURIComponent(challenge))); // UTF-8 → base64
   ws.send(JSON.stringify({
     module: 'kz.gov.pki.knca.commonUtils',
     method: 'createCAdESFromBase64',
     args: ['PKCS12', 'SIGNATURE', base64Data, true],
   }));
   ```
   Последний аргумент `true` (attached) **обязателен**: подписанные данные
   должны оказаться внутри CMS, иначе сервер не сверит их с challenge.
3. Ответ отличается в разных версиях NCALayer:
   - подпись — в `response.responseObject` **или** строкой в `response.result`;
   - ошибка — `response.code` не равен `'200'`, текст в `response.message`
     (отмена пользователем, неверный пароль от ключа и т.п.).
4. Закрыть WebSocket и отправить `{challenge, signature}` на `/api/auth/login-2fa`.

Показывайте пользователю этапы: «Подключение к NCALayer…», «Подпишите данные
в окне NCALayer…», «Проверка подписи…», и текст ошибки от сервера.

## 6. Проверка перед выкладкой

| Сценарий | Ожидание |
|---|---|
| Пользователь без ИИН | Вход по паролю, окно NCALayer не появляется |
| Пользователь с ИИН, своя ЭЦП | Окно NCALayer → вход |
| Чужая ЭЦП | 401 «ИИН в ЭЦП не совпадает с аккаунтом» |
| Подпись через 5+ минут после выдачи challenge | 401 (challenge истёк) |
| NCALayer не запущен | Понятное сообщение, без зависания |
| Вход в этот сайт при открытом geo на том же хосте | Сессия geo не слетает (разные имена cookies) |

## 7. Прорисовка логотипа на странице входа

Как в geo: при открытии страницы входа логотип «рисуется» — сначала контуром
прорисовываются буквы, затем они заливаются цветом, в конце так же
прорисовывается фирменный знак. Без библиотек: инлайновый SVG и SMIL-теги
`<animate>`.

### 7.1. Подготовка логотипа

- Нужен SVG, где **буквы — контуры (`<path>`), а не текст**. Если логотип
  сделан текстом, переведите его в кривые в редакторе (Figma: Outline stroke /
  Flatten).
- SVG вставляется в разметку формы входа **инлайном**, над заголовком. Через
  `<img>` или CSS-фон анимация не будет управляемой.
- Из исходника берутся только пути самого логотипа (без служебных надписей,
  направляющих и т.п.), `viewBox` — по их границам с небольшим запасом.
- Пути букв сортируются **слева направо** (по первой координате X), чтобы
  буквы рисовались по порядку.
- Разметку с десятками путей удобнее генерировать скриптом (в geo так и
  сделано: Python читает SVG, сортирует пути и печатает готовый блок), чем
  писать руками.

### 7.2. Приём для каждой буквы

Каждый путь буквы выводится **дважды**:

```html
<!-- 1. Контур: «рисуется» пером, потом гаснет -->
<path d="…" fill="none" stroke="#18140F" stroke-width="0.55" stroke-linejoin="round"
      pathLength="1" stroke-dasharray="1 1" stroke-dashoffset="1">
  <animate attributeName="stroke-dashoffset" from="1" to="0"
           begin="T0s" dur="0.55s" fill="freeze"/>
  <animate attributeName="opacity" from="1" to="0"
           begin="(T0+0.48)s" dur="0.35s" fill="freeze"/>
</path>
<!-- 2. Заливка: проявляется, пока контур дорисовывается -->
<path d="…" fill="#18140F" opacity="0">
  <animate attributeName="opacity" from="0" to="1"
           begin="(T0+0.36)s" dur="0.35s" fill="freeze"/>
</path>
```

- `T0 = 0.15 + 0.055 × i`, где `i` — номер буквы слева направо. Значения
  `begin` подставляются уже посчитанными числами, например `begin="0.26s"`.
- `pathLength="1"` нормирует длину любого контура к единице — поэтому одни и те
  же `stroke-dasharray="1 1"` и `stroke-dashoffset` 1 → 0 работают для букв
  любого размера.
- `stroke-width` задаётся в единицах `viewBox`. 0.55 подобрано под логотип
  высотой 43 единицы с буквами около 11 единиц. Для другого логотипа берите
  примерно 5% высоты буквы: тоньше — контур не виден, толще — буквы слипаются.
- `fill="freeze"` у всех `<animate>` — в конце логотип остаётся в финальном виде.

### 7.3. Мелкий текст

Строки мелким шрифтом (подзаголовок, расшифровка названия) контуром **не
рисуются** — при такой высоте обводка сливается в кашу. Они проявляются с
лёгким подъёмом, одна за другой, когда буквы почти закончились:

```html
<g opacity="0">
  <animate attributeName="opacity" from="0" to="1" begin="Ts" dur="0.5s" fill="freeze"/>
  <animateTransform attributeName="transform" type="translate" from="0 3" to="0 0"
                    begin="Ts" dur="0.5s" calcMode="spline" keySplines="0.25 0 0.2 1"
                    fill="freeze"/>
  <path d="…" fill="#18140F"/>
</g>
```

`T` — момент окончания заливки последней буквы минус 0.25 с, у следующей
строки +0.18 с.

### 7.4. Фирменный знак

Рисуется **последним**, тем же приёмом «контур → заливка», но медленнее и с
плавным замедлением:

- контур: `stroke-width="0.8"`, `dur="0.85s"`, `calcMode="spline"`,
  `keySplines="0.3 0 0.2 1"`;
- если знак из нескольких частей — каждая следующая стартует на 0.28 с позже;
- заливка: `begin` = старт контура + 0.6 с, `dur="0.45s"`;
- контур гаснет: `begin` = старт заливки + 0.2 с, `dur="0.4s"`.

Вся последовательность — около 3 секунд.

### 7.5. Размер

```css
#auth-logo { display:block; width:228px; height:auto; margin:2px auto 26px; overflow:visible; }
```

`overflow:visible` нужен, чтобы обводка у краёв не обрезалась.

### 7.6. Повторный показ страницы входа

Из-за `fill="freeze"` логотип после проигрывания остаётся дорисованным. Если
страницу входа показывают снова без перезагрузки (например, при выходе из
аккаунта), сначала откатите анимацию в нулевую точку, иначе на экране мелькнёт
готовая надпись:

```js
const logo = document.getElementById('auth-logo');
try { logo.pauseAnimations(); logo.setCurrentTime(0); }
catch (e) { logo.style.opacity = '0'; }   // браузер без управления SMIL
```

В нулевой точке ни одна `<animate>` ещё не началась, и действуют исходные
значения разметки — заливки с `opacity="0"`, контуры с `stroke-dashoffset="1"`,
то есть логотип пуст.

## 8. Где смотреть рабочий пример

Репозиторий geo:
- `backend/app/core/eds.py` — challenge и разбор CMS;
- `backend/app/api/routes/auth.py` — `/login` и `/login-2fa`, выдача cookies;
- `frontend/index.html` — блок «ЭЦП РК (NCALayer)»: подключение, handshake,
  запрос на подпись, разбор ответа; `<svg id="auth-logo">` — прорисовка
  логотипа; функция `doLogout()` — откат анимации логотипа при выходе;
- `migrations/versions/0009_user_iin.py` — поле ИИН у пользователя.

Всё повторять как есть, кроме имён cookies и секрета JWT.
